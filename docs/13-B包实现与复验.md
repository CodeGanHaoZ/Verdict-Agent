# B 包实现、联调与复验

本轮实现对应用户要求的 B 包：三个实际 HTTP 签名服务 → 候选选择 → A 内核逐次验收 → 预算内替换或停止 → SQLite／内容寻址证据 → 第二实例独立重验并影响选择。A 的 schema 1.0.0、eth-account-v1 规则和签名语义未修改；新增 API 业务类型版本为 1.0.0。C 的网页、真实存证适配器和合约未实现。

## 1. 可复跑命令

在仓库根目录，使用 `.nvmrc` 的 Node 22.23.3 / npm 10.9.9：

```bash
npm ci --ignore-scripts
npm run typecheck
npm run test:all
npm run dev:init
npm run dev:start
npm run example:b -- http://127.0.0.1:3001 success
npm run example:b -- http://127.0.0.1:3001 fallback
npm run example:b -- http://127.0.0.1:3001 all-fail
npm run verify:b
npm run observe:b
npm run dev:stop
```

`dev:init` 构建后生成本地演示密钥和两套实例配置，不覆盖已有文件。依赖安装需要网络；集成测试和签名服务使用真实冻结证明，可以离线执行。`observe:b` 需要网络；真实响应或限制均原样分类，不要求现场出现某种故障。

`dev:start` 实际启动五个 Node 进程：demo 服务在 14301、14302、14303，后端在 3001、3002。分别使用 `.local/b-demo/local-one.json`、`local-two.json` 可信配置，数据库与证据位于 `.local/instances/local-one/`、`local-two/`。日志、进程记录、复验摘要和网络观测留在 `.local/b-demo/`。停止检查 Linux `/proc` 中本轮 launchId，仅结束自己启动的进程，保留数据。

单独运行第二实例：`npm run server -- --config .local/b-demo/local-two.json`；单独运行签名服务：`npm run demo:service -- --config .local/b-demo/demo-valid.json`。前台用 Ctrl-C 停止。不要与统一启动重复占用同一端口／数据库。公共 RPC 通过 Node `--use-env-proxy` 支持现有环境代理，loopback 应加入 `NO_PROXY`；统一脚本已处理。

## 2. 已执行结果与来源

实际五进程演示得到：两个签名前注入的错误交付分别产生 `BLOCK_MISMATCH`／`FIELD_MISMATCH`，归属均为 VERIFIED；后端拒收后换用 demo-valid，得到 PASS。仅选择两个错误服务时得到 STOPPED／NO_ACCEPTABLE_DELIVERY，accepted=null。原始规范化包下载后由第二实例重新计算摘要、签名、账户证明、请求条件及本机信任策略。

排序对照固定 task、配置和观测，只切换 `useHistoricalEvidence`。在 demo-wrong-block 与 demo-valid 两候选间，关闭历史证据时前者在先，启用一份适用反证后 demo-valid 在先；第二实例随后发出新请求，仍执行 A 的验收才采用。其他场景同时验证错值反证的独立重算。第一实例原报告不能决定第二实例结果。

2026-10-07 UTC（本地 10 月 6 日）的实际网络采样使用两家公共端点，各六次请求，账户为 WETH：

| 实测项目 | dRPC `eth.drpc.org` | PublicNode `ethereum-rpc.publicnode.com` |
| --- | --- | --- |
| `eth_chainId` | HTTP 200，1 | HTTP 200，1 |
| `eth_getBlockByNumber(finalized)` | 返回区块 26137756 | 返回区块 26137756 |
| `eth_getBlockByNumber(24000000)` | 返回匹配冻结样本的区块哈希 | 返回匹配冻结样本的区块哈希 |
| `eth_getProof(latest)` | 返回证明节点 | 返回证明节点 |
| `eth_getProof(24000000)` | 返回证明节点 | HTTP 403，ERROR/UNKNOWN |
| `eth_getProof(26134149 的固定哈希对象)` | 返回证明节点 | RPC -32602，UNSUPPORTED |

这轮 12 次采样为 10 OK、1 ERROR、1 UNSUPPORTED，耗时约 255–1544 ms/请求。403 不能推断为永久不支持，参数／范围限制不能外推为服务全面不可用。429、超时、缺证明和其他失败通过独立的受控测试验证，不能称为本次真实提供商事故。返回证明材料的格式支持也不是数据 PASS，公开 RPC 本身没有提供本项目服务签名。

离线检查包括原 A 包 48 项和 B 包 22 项集成测试；覆盖并发、预算、未知规则、输入、错误身份、篡改、失效授权、重启及发布失败。最终运行结果以命令退出状态和本地运行材料为准，不把 CI 配置文件称为远端 CI 已通过。

## 3. API 及 C 接线

完整共享运行时 schema 从 `@verdict/protocol` 导入：CreateRunSchema、CandidateSchema、RunSnapshotSchema、ReplaySnapshotSchema、ObservationSchema、PublicationSchema。浏览器无需导入 core、SQLite 或后端私有代码。

| 方法与路径 | 请求与结果 |
| --- | --- |
| GET `/health` | instanceId、apiVersion、launchId |
| GET `/api/meta` | 可用 contextId、已配置检查点／策略、演示账户能力；不含密钥和私有路径 |
| GET `/api/services` | `{apiVersion,candidates}`，声明、实际观测、指标、来源和理由；无 task 时不是最终任务排序 |
| POST `/api/selection` | CreateRun → `{apiVersion,candidates}`，仅比较选择，不调用交付服务 |
| POST `/api/runs` | `{task,contextId,candidateIds?,useHistoricalEvidence?}` → 202 `{runId,duplicate}`；历史证据默认启用 |
| GET `/api/runs/:runId` | RunSnapshot；轮询至 SUCCEEDED、STOPPED 或 ERROR |
| GET `/api/evidence` | 索引条目及发布状态 |
| GET `/api/evidence/:id` | manifest、重新检查的文件完整性、下载链接、contextId、本机评估时间、复验任务和发布状态 |
| GET `/api/evidence/:id/bundle` | 保存的原始 JCS 字节；每次读取检查摘要，篡改或缺失返回 422 |
| GET `/api/evidence/:id/manifest` | 下载配套 manifest |
| POST `/api/evidence/import` | `{bundle,manifest,contextId}`；真实重验通过索引门槛后返回 evidenceId、result、consistent；不要求数据一定 PASS，允许已验证反证 |
| POST `/api/replays` | `{evidenceId,contextId}` → 202 `{replayId}` |
| GET `/api/replays/:replayId` | 状态、A 重算结果、reportConsistent、错误 |
| GET `/api/observations` | 已记录观测 |
| POST `/api/observations` | `{}`，探测已配置 RPC 白名单；并发调用共用正在执行的一轮，约最多 96 秒 |

任务幂等范围是本实例数据库；签名服务另有自己的幂等表。复验 POST 每次创建新计算任务，以便重跑更新后的可信策略，不触发数据采用或发布。

请求错误 400、未知资源 404、重用 requestId 但输入不同 409、未接受的来源／证据 422、服务端异常 500。验收 FAIL、UNVERIFIABLE 与停止为业务结果，GET 快照仍返回 200。请求体最多 2 MiB，响应获取有同样上限；JSON 拒绝重复键。默认仅允许 localhost:5173 和 127.0.0.1:5173 的 CORS 来源，实例仅绑定 loopback。

最小 API 消费例，使用真实本地配置生成请求：

```js
import { api, consume } from '@verdict/consumer';
const base = 'http://127.0.0.1:3001';
const meta = await api(base, '/api/meta');
const context = meta.contexts[0];
const now = Math.floor(Date.now() / 1000);
const run = await consume(base, {
  contextId: context.contextId,
  useHistoricalEvidence: false,
  candidateIds: ['demo-wrong-block', 'demo-wrong-value', 'demo-valid'],
  task: {
    schemaVersion: '1.0.0', requestId: crypto.randomUUID(), dataChainId: '1',
    account: meta.capabilities[0].accounts[0], blockHash: context.trustedBlock.blockHash,
    fields: ['balance', 'nonce', 'codeHash', 'storageRoot'],
    evidencePolicyId: context.policy.id,
    validity: { notBefore: String(now - 5), expiresAt: String(now + 300) },
    budget: { maxAttempts: 3, timeoutMs: 15000, maxCostWei: '0' }
  }
});
if (run.status !== 'SUCCEEDED' || !run.accepted) throw new Error(`停止依赖: ${run.stopReason}`);
console.log(run.accepted.values, run.accepted.evidenceId);
```

`RunSnapshot.accepted` 只包含本次 PASS 的 `{serviceId,evidenceId,blockHash,values}`，只暴露所请求的已验证字段。失败过程中其他服务返回的值在不可变证据内保留供审计，不能作为 accepted 使用。attempts 的 status 为 RUNNING/COMPLETED/INTERRUPTED；RUNNING 时 observationStatus 尚未定案，C 应显示等待。attempts 中保留每次 observationStatus、runtimeReason、verification、evidenceId、耗时和预留成本（attempt.latencyMs 含核验，Observation.latencyMs 只计服务响应）；C 直接使用 verification.checks 展示逐项结论。

跨实例复制与复验（不复制可信配置）：

```js
const id = run.attempts[0].evidenceId;
const bundle = await api(base, `/api/evidence/${id}/bundle`);
const manifest = await api(base, `/api/evidence/${id}/manifest`);
await api('http://127.0.0.1:3002', '/api/evidence/import', {
  bundle, manifest, contextId: 'mainnet-demo'
});
const { replayId } = await api('http://127.0.0.1:3002', '/api/replays', {
  evidenceId: id, contextId: 'mainnet-demo'
});
console.log(await api('http://127.0.0.1:3002', `/api/replays/${replayId}`));
```

## 4. 原子性、核验与排序

SQLite WAL 持久化请求、快照、原子消费、观测、证据索引和复验。独立 writer.sqlite 的进程生命周期独占事务限制单写者，进程死亡自动释放锁，避免并发重启争抢陈旧 PID 文件。task/requestId 与包括 contextId、candidateIds、历史开关在内的完整输入摘要一同登记。相同请求重复／并发只会得到同一个 runId，不会再次调用和采用；冲突输入返回 409。签名服务另有自己的请求幂等表。对应用调用方返回事实卡不等于替其完成支付等外部副作用，调用方仍需以 runId 做自己的幂等处理。

一次调用前持久化报价预留；未知报价排除，不能当免费。预算按最坏情况预留总成本，无真实支付；失败也不退预算。总时间含选取、请求和核验，达到限制后不采用迟到的 PASS。有效候选按次数／时间／成本预算有界替换。崩溃重启将不确定的 QUEUED/RUNNING 标为 STOPPED/INTERRUPTED，保留已成功原子消费；不尝试远端调用的分布式 exactly-once 重放。

硬条件过滤链、区块、账户、字段、证明、签名与已知价格；未知范围保留明确 UNKNOWN，允许当前有界尝试。最近五分钟内同账户／区块／版本的实际 unsupported 暂时排除；限流、超时不会变成永久不支持。当前交付即使验证 PASS，若 serviceId/version 与所选候选不同，也以 SERVICE_ID_MISMATCH 拒用。

排序依次为：硬条件 → 是否有适用反证 → 配置中的来源组顺序 → 同来源／同任务范围本地失败率 → 已知报价 → 可比延迟 → 配置顺序。来源分组避免实时、冻结、故障注入之间不成立的性能比较。理由在 Candidate 中返回，无全局信誉分。统计按来源、方法、区块、24 小时窗口保存分子／分母；验收数量只计本机实际调用，导入记录不会增加本机成功次数。

历史反证先从 CAS 读取、检查摘要，再调用 replay_evidence 和 fact_key。需要服务／版本、链、账户、区块、字段、证据策略一致，本机接收年龄在范围内，密钥当前仍授权。相同事实即使不同 requestId／签名／转发包也只分一组；排序只使用“有／无适用失败”，不按票数加权。旧反证只降低优先级，修复后的当前交付仍可通过。最多检查最近 256 份记录，暂不做大型证据检索系统。

导入不会采用 bundle 内的 baseline／授权作为信任源。本机 contextId 决定检查点、规则、密钥、政策和时间。允许本机时钟／历史模式产生 CONTEXT_DIFFERENT，但另外严格比较重算报告，仅对已通过的有效期与重放模式的上下文显示值归一化；数据／签名检查、状态、原因、要求与基准都不能被替换。UI_MOCK、未知规则、摘要不符、报告伪造和不符合配置的来源均拒绝入索引。

## 5. 发布边界与限制

发布状态独立保存。C 尚未提供真实 adapter，默认 `status=not_requested, adapter=not_configured`。内部 `publishForTest` 只在显式测试配置下运行，原子登记 pending 后产生 `INJECTED_TEST_ADAPTER_FAILURE`；不创建链上交易、哈希或 confirmed。重试需提供上一失败 attemptId，过期／重复重试不会造成多次消费。进程重启把遗留 pending 标 failed/INTERRUPTED；发布失败不改写验收证据和任务结果。没有公开任意花费 Gas 的接口。

当前已完成 B 的本地后端闭环；仍存在以下边界：

- 公开 RPC 接入是实时能力观测；受控签名服务使用审阅过的冻结材料，不代表 RPC 厂商提供项目签名或可任意动态请求所有区块。
- 区块与密钥由操作者显式固定，未验证以太坊共识／最终性，也未完成 ERC-8004 身份注册；两实例默认由同一操作者配置。
- 首次导入已过有效期的包需要配置可信历史评估时间；不能从待验包推导信任时间。
- 本地单写者后端，无公众多租户认证、分布式队列、数据库归档／分页、资源配额或生产部署；网络读取和单任务有预算，小型历史扫描有上限。
- C 网页、真实存证适配器／合约／链上确认、浏览器 e2e 未完成。模型／PI、支付、复杂信誉、更多任务类型和主网部署不在本轮实现范围。

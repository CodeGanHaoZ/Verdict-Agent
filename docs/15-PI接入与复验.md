# PI Agent：直接执行与真实模型复验

按 [009 用户最新决定](decisions/009-direct-pi-agent.md)，直接定制 `@earendil-works/pi-agent-core@1.0.4` 与 `pi-ai@1.0.4`。任务进入 PI 工具循环，页面不再经过草案确认。没有替换 PI 循环、复制上游内核或引入 coding-agent 的终端／文件权限。

## 实际流程

输入任务 → PI 调用 `start_task` 绑定条件 → 自主选服务 → 真实签名交付与 A 核验 → 根据失败换候选／复验／停止 → 输出辅助说明与证据。

模型负责选择和工具调用；确定性代码负责预算、签名、证明、请求绑定、证据与原子采用。只有当前交付通过才有 accepted。绑定后账户、区块、候选范围与预算不可变；同候选重复调用不重复产生副作用，成功后不能继续调用交付。缺少账户、固定区块或不支持“最新状态”时，PI 说明缺项并停止，不替换成冻结样本。

工具为 `start_task`、`find_service`、`request_verified_state`、`get_evidence_summary`、`replay_evidence`、`stop_task`。证据操作复用已有 A/B 实现；另一实例按自己的可信配置重新验签、验证明和检查请求。自由证据文字不作为指令，模型说明不进入公共证据。

## 真实接口初测

2026-10-07 使用用户指定的 `https://api.modelarts-maas.com/plan/v2`，请求模型 `GLM-5.3`，接口回报 `glm-5.3`。单次工具连通性测试通过；直接 PI 已完成：

- 错块 FAIL → 错值 FAIL → 正常 PASS，5 次模型请求，4 次工具调用，实际三个服务各调用一次。
- 全失败 STOPPED，6 次模型请求，5 次工具调用，两个服务各调用一次，没有 accepted。
- 错值 FAIL → PI 调用 local-two 重算并确认 FAIL → 正常 PASS，6 次模型请求、5 次工具调用；第二实例具有独立进程、可信配置和数据库。
- 最新状态请求：1 次真实模型请求后说明当前检查点限制，未绑定数据任务、三个服务调用数均为零。

汇总报告留在本机 `.local/pi-live/summary.json`，引用每轮原始报告；首轮 fallback 的输入早于预算文字补充，保留了当时 caseHash。初轮只实测以上 4 条；后续已补齐其余 6 条真实测试并增加 20 条盲测，包含模型超时和复验缺陷，见 [360 评测](17-360异常评测.md)。

第一次沿用旧通用配置时，1024 tokens 全部用在原生思考，工具未发出；尝试关闭思考得到 HTTP 400。失败如实保留于本地报告，未使用固定流程替代。最终显式使用 `compatibility=glm`、`max_tokens=4096`，不发送不支持的 thinking 开关；没有展示或保存隐藏推理文本。模型输入／输出／缓存用量单独记录，未配置价格，因此费用为未知，不宣称免费。

以上是小样本机制验证，非稳定性或吞吐承诺。模型之外的交付数据是已有主网冻结证明；故障是本地签名前注入，不能称为真实 RPC 厂商事故。

## 启动与复跑

Node 22.23.3 / npm 10.9.9。仅模型后端使用密钥环境变量，不自动读取其他应用的凭据。

```bash
npm ci --ignore-scripts
export VERDICT_PI_BASE_URL='https://api.modelarts-maas.com/plan/v2'
export VERDICT_PI_MODEL='GLM-5.3'
export VERDICT_PI_COMPAT='glm'
export VERDICT_PI_OUTPUT_TOKENS='4096'
export VERDICT_PI_KEY_ENV='VERDICT_PI_API_KEY'
# 在本机安全设置 VERDICT_PI_API_KEY，不在命令历史或文档中写实际密钥。
npm run dataset:check
npm run verify:pi:local                 # 4 条 smoke，临时端口、独立五进程、结束后清理本次进程
npm run verify:pi:local -- all-fail
npm run verify:pi:local -- replay-before-fallback
```

如果密钥保存在本机权限 0600 的 `.local/pi-live/model.env`，可通过 Node 读取，避免在命令行传密钥值：

```bash
npm run build
node --env-file=.local/pi-live/model.env scripts/dev/verify-pi-local.mjs
```

上述 endpoint/model/compat/output 环境变量仍需设置。每次运行输出 `.local/verify-local-*/evaluation.json`，记录成功与失败、caseHash、工具调用、实际核验、用量；`*-evidence.json` 保存完整 bundle＋manifest。脚本只给第一后端传指定模型密钥，第二实例与签名服务没有模型访问权限。

持续网页演示：

```bash
npm run dev:init
npm run pi:configure -- .local/b-demo/local-one.json
npm run dev:stop
node --env-file=.local/pi-live/model.env scripts/dev/control.mjs start
npm run web
# http://127.0.0.1:5173 → PI Agent → 输入任务 → 运行 Agent
npm run dev:stop
```

固定流程 API 和网页仍可独立使用。模型未配置时明确显示不可用，模型失败不自动降级。

## API 与持久化

| 路由 | 输入／行为 |
| --- | --- |
| GET `/api/agent/meta` | 配置可用性、模型 ID、来源与服务预算，无密钥 |
| POST `/api/agent/runs` | `{clientRequestId,prompt}` → 202 `{agentId,runId,duplicate}`；立即执行 |
| GET `/api/agent/runs/:id` | AgentSnapshot 1.1.0；绑定前 runId=null，直接运行 draftId=null |
| GET `/api/agent/runs/:id/events?after=0` | 按序号读取模型请求、工具和辅助说明，无隐藏推理 |
| POST `/api/agent/runs/:id/stop` | `{}`；取消后续操作并保留证据 |
| GET `/api/runs/:runId` | 原有真实 RunSnapshot、检查与 accepted |

相同 clientRequestId＋输入并发提交只创建一个 Agent；不同输入复用 ID 返回 409。agent_requests 持久化直接请求映射；未完成 Agent 重启后标记 INTERRUPTED，不自动重跑。页面提交响应丢失时保留同一请求，查询中断可恢复原 Agent。旧草案 API 保留供既有调用方兼容，但不是当前网页或直接执行的前置条件。

默认 `runRequests=8`、`toolCalls=12`、`requestTimeoutMs=30000`、`outputTokens=1024`（GLM 本次显式设为 4096）、总预算 180 秒、3 次服务尝试、0 wei；操作者允许的 outputTokens 范围为 64–8192。SDK 重试关闭。服务预算与模型 tokens／费用分别记录。模型异常、限流、超时、取消或超预算停止后续操作；已原子采用的数据不因后续解释失败被撤销。

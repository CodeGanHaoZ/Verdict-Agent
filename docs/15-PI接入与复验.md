## 运行与配置

Node 22.23.3，仓库根目录：

```bash
npm ci --ignore-scripts
npm run dev:init
# 设置自己实际使用的兼容接口与模型；值仅用于生成本地配置
export VERDICT_PI_BASE_URL='https://your-provider.example/v1'
export VERDICT_PI_MODEL='your-tool-capable-model-id'
export VERDICT_PI_KEY_ENV='VERDICT_PI_API_KEY'
npm run pi:configure -- .local/b-demo/local-one.json
# 在本机安全设置 VERDICT_PI_API_KEY 的真实值，不写入公共文档或聊天
npm run dev:start
npm run web
```

如果 B 已运行，先 `npm run dev:stop`，再从含密钥环境变量的终端 `npm run dev:start`。密钥只从服务器进程的指定环境变量读取，不自动发现其他应用的登录凭据。配置 JSON 只记录变量名，浏览器从 `/api/agent/meta` 获取可用性和模型 ID，不读取 key、baseURL 或服务器私有路径。

`agent` 配置可选。默认初始化不会配置模型，界面显示未配置，原固定流程不受影响。`pi:configure` 显式更新指定本地 JSON 的 agent 字段，并提供 WETH 别名及 local-two 复验目标；其他地址别名、模型价格或端口可由操作者在本地配置编辑。

参数及默认值：`draftRequests=2`、`runRequests=8`、`toolCalls=12`、`requestTimeoutMs=30000`、`outputTokens=1024`、`maxDurationMs=180000`、`maxAttempts=3`、`maxCostWei="0"`。另外 `maxInputChars=32000` 限制发给模型的上下文规模，`contextWindow=32768` 为配置元数据，需与模型匹配。上限通过运行时 schema 限定，模型不能提高。

模型用量单独记录 input/output/cache tokens；可配置每百万 token 的价格 `pricePerMillion`。没有价格时 `costUsd=null`，不得表示免费。服务 wei 报价／预留与模型计费不是同一个预算。SDK 重试为 0；单请求超时、全程超时和轮次数分别生效。API 不设置模型温度或推理参数，不假设所有兼容提供商支持它们。

## 流程与接口

`apps/server/src/agent-service.ts` 是业务会话层，`pi-runtime.ts` 只绑定 PI 的模型调用、顺序工具、限制与公开事件；`engine.ts` 的受限单次执行器供固定流程和 PI 共用。证据和 A 规则未修改。

| 路由 | 行为 |
| --- | --- |
| GET `/api/agent/meta` | 模型是否配置、框架版本、模型 ID、来源与默认预算 |
| POST `/api/agent/drafts` | `{clientRequestId,prompt}` → 202 `{draftId,duplicate}`；相同请求幂等，冲突 409 |
| GET `/api/agent/drafts/:id` | 草案、版本、缺失条件、用量及错误；生成阶段不调用交付服务 |
| POST `/api/agent/drafts/:id/revise` | `{version,conditions}` → 保存用户核对的条件，新版本加一；超限／未知策略不接受 |
| POST `/api/agent/drafts/:id/confirm` | `{version}` → 202 `{agentId,runId,duplicate}`；仅 READY 且未过期的当前版本可确认 |
| GET `/api/agent/runs/:id` | AgentSnapshot，包括模型状态、运行来源、错误、简短说明和关联 runId |
| GET `/api/agent/runs/:id/events?after=0` | 按 sequence 增量获取最多 200 条事件，不发送隐藏推理 |
| POST `/api/agent/runs/:id/stop` | `{}` → 幂等停止后续 Agent 操作，保留已完成证据 |

`conditions` 包括 contextId、account、blockHash、fields、candidateIds、useHistoricalEvidence、budget。用户不能通过它注入新 URL、签名授权或另一个 policy。确认时生成新的 requestId／有效期，把全部条件锁定后原子绑定 Agent 与 run。草案有效期十分钟；用户保存修改后重新计时。已确认草案禁止编辑，重复确认同版本返回同一结果。

自然语言不能可靠确定条件时保留 null 和 missing；账户必须出现在请求中或匹配操作者提供的别名。固定区块必须明确指定哈希或表达选用检查点。“最新状态”没有明确哈希时强制保留缺项，必须由用户主动选检查点并保存新版本，不能静默转成冻结材料。

前端提供固定流程／PI 模式切换；PI 先生成草案，核对账户、区块、字段、候选和预算，再确认。模型输出为辅助文字；右侧事实卡只来自真实 RunSnapshot.accepted。刷新恢复当前模式下的原任务；确认响应丢失后重试相同版本不重复消费。

## 工具与信任边界

正式执行仅允许五个工具：

- `find_service()`：当前任务的候选、来源、资格、解释理由与适用证据 ID。
- `request_verified_state({serviceId})`：一次服务调用＋强制验收＋证据保存；只返回已经采用的值，失败时只有状态、原因和材料引用。
- `get_evidence_summary({evidenceId})`：重算限定证据后给检查状态与引用，不给原始未验值／可执行描述。
- `replay_evidence({evidenceId,targetId})`：local 或操作者配置的复验目标。远端走 import 的真实重验，密钥和检查点由目标实例自己配置。
- `stop_task()`：停止数据依赖，不采用任何未验数据。

证据 ID 必须属于本任务已产生的交付，或由 `find_service` 返回的适用历史记录。工具输入不允许额外字段，不能传入放宽后的任务、授权、预算或任意下载地址。模型不能直接操作 SQLite、文件系统、shell 或上链接口。证据 provenance 自由文字不进入模型上下文；模型拿到的是白名单结构化元数据，公共证据中不写聊天、模型凭据或自报解释。

同任务、同候选的并发／重复调用共用一次结果；不同候选不能并发产生副作用。每次实际调用再次过滤能力和预算，签名／证明始终由 A 包执行。成功后任何新交付工具都拒绝，哪怕模型在同一批里预先排了多次调用。只说“PASS”且没有实际核验的模型输出最终得到 NO_VERIFIED_RESULT。

## 异常、持久化与复验

SQLite 增量添加 agent_drafts、agents、agent_events；不改现有证据格式和 A schema/rule。草案修改、确认、请求登记、Agent/run 绑定在同一事务内完成。事件有递增序号，可轮询恢复。草案生成／Agent 未完成时重启分别标 INTERRUPTED，不自动恢复模型或服务副作用。

限流、超时、模型轮次／工具上限、非法参数、用户取消与总预算耗尽分别记录。不会自动改成固定流程。取消会中断模型及后续服务调用；网络取消不承诺撤销服务端已收到的请求，幂等记录防止再次调用。

模型停止后仍无 accepted 数据则明确停止依赖。数据已原子采用后，模型追加调用或解释错误只将 Agent 标为错误，RunSnapshot 仍保存真实 SUCCEEDED，已保存证据保持原结论。前端可同时看到这两个状态。

```bash
npm run typecheck
npm run test:all
npm run test:e2e
npm run verify:b
# 仅在 LIVE 接口实际配置后运行；输出本轮真实模型执行摘要
npm run verify:pi
```

`verify:pi` 发起两笔真实模型任务：按指定顺序错误替换至 PASS，以及全失败停止，结果写入忽略目录 `.local/pi-demo/live-verification.json`。CI 使用测试传输验证硬约束；模型配置错误不能被解释为真实联调已通过。

剩余边界：仅支持当前以太坊账户字段和已配置检查点，不含自动共识／最新区块信任获取、多租户、分布式队列、跨重启自动续跑、完整通用聊天、钱包、支付、真实链上存证或主网部署。

## 3. 实际遇到的数据可用性限制

- dRPC 本轮成功提供五个历史高度及现有高度的账户证明，不能据此保证任意过去状态或无限查询额度。
- PublicNode 对部分合并前的区块头查询返回历史裁剪限制。1RPC 按高度取得旧头后可以与已固定的哈希核对；不同方法和后端的支持可能不同，不能只测一次就给提供商永久能力标签。
- 一次 LlamaRPC 请求返回 HTTP 525，只记录本次访问失败，不作为数据造假的依据。
- 现有 `capture.py` 已增加显式 `--baseline-source` 和可重复 `--account`，保留数量上限。不会把无法获取的证据补成通过，也不采购付费 RPC。

## 4. 下一批优先补的覆盖

1. **精确分叉边界**：选择 London、Shanghai、Cancun、Prague 等激活前后相邻块，补齐头字段必须出现／必须缺失的真实对照。当前跨时期样本不等于已经完成这些边界测试。
2. **更多账户状态**：真实存在但为空的账户、授权代码账户等；必须先找到可核验对象和完整证明，不能只根据地址标签推断。
3. **证明结构负例**：从官方 Trie 向量中选少量可解释案例，标为合成数据，与主网快照分开。
4. **不同 RPC 的表示差异**：对同一块和账户比较不存在值、字段编码和证明范围限制；保留原始响应，不静默修改已签名材料。

服务商签名、实际生产投诉和独立第三方复现尚无现成数据。本地适配器签名与人工故障注入可以验证机制，不能冒充这些数据来源。

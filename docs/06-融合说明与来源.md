| 主题 | 融合处理 |

## 3. 不能照搬的断言与冲突

| 初稿中的表述或冲突 | 修订 |
| --- | --- |
| 无签名一律表示数据不可核验 | 分开 dataVerdict 与 attributionStatus；无签名也可能有有效数据证明 |
| 429／限流作为 UNSUPPORTED | RATE_LIMITED 独立记录；明确的能力或历史范围限制才标 UNSUPPORTED |
| 旧区块必然陈旧 | 是否不符取决于请求；正确的历史目标可以通过 |
| 三态、STALE、UNSUPPORTED 混用 | 三态是请求主结果，限制与错误用原因码；签名归属另列 |
| 账户和存储证明都在 P0，同时存储槽又列 P2 | P0 仅账户证明与字段；任意存储槽留 P2 |
| 哈希重算等于所有链上可信性已解决 | 仍需目标区块的网络归属、最终性和独立基准策略 |
| 验签自动防重放 | 补充域、请求 ID、有效期、历史绑定与重复响应规则 |
| 任意 canonicalJson 即可生成稳定摘要 | 明确 schema 与规范化候选、整数／字节编码，并避免正文包含自身哈希 |
| 链上锚定、ERC-8004 feedback 必须同步完成 | 本地／测试验证和主网工作线分开；存证不等于验真，实际部署未完成 |
| x402 是验收后托管退款基础设施 | 只作为支付接入候选，验收条件、托管和争议机制需要独立设计 |
| 确认人数不加权就“堵死女巫攻击入口” | 限制为重复事实不放大权重；不承诺识别主体、阻止身份洗白或垃圾请求 |
| “Agent 服务的 CVE”暗示事故认定 | 使用轻量审计记录与证据索引，不暗示官方 CVE 编号或漏洞定级 |
| 第三方 Agent 一行接入为现成能力 | 拟议最小接口是设计目标；安装、配置与适配还未实现 |
| 列举多起事故即能防止同类损失 | 删除未逐案核实的事故和预防效果断言，使用可测试的故障类型 |
| 40 小时／38 小时被当作当前剩余时间 | 作为历史规划背景，恢复实施时重新估算，不虚构当前预算 |

## 4. 技术来源与本次核查

本次为文档融合和只读资料核查，未运行服务验收实验。

| 来源 | 本次采用的事实或边界 |
| --- | --- |
| [EIP-1186](https://eips.ethereum.org/EIPS/eip-1186) | 相对区块头的 stateRoot 验证账户／存储值，仍依赖可信区块哈希；本次已重读相应说明 |
| [EIP-712](https://eips.ethereum.org/EIPS/eip-712) | 类型化数据签名；标准明确不内置重放保护，本次已核查 |
| [EIP-1898](https://eips.ethereum.org/EIPS/eip-1898) | blockHash 与 requireCanonical 语义；具体方法和提供商支持未实测 |
| [ERC-8004](https://eips.ethereum.org/EIPS/eip-8004) | 身份与反馈登记机制；页面为草案，实际部署 ABI 和可用性尚未核验 |
| [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785) | JSON 规范化候选；采用前还需选择实现、固定 schema 并运行向量 |
| [x402 上游](https://github.com/x402-foundation/x402) | 定位为互联网支付标准，不据此宣称已具备本产品所需的验收托管；本次读取的 Coinbase 仓库指向该上游 |
| [EthereumJS MPT](https://github.com/ethereumjs/ethereumjs-monorepo/tree/master/packages/mpt) | 证明处理库候选，版本与兼容性待最小验证 |
| [EthereumJS 证明用例](https://github.com/ethereumjs/ethereumjs-monorepo/blob/master/packages/mpt/test/proof.spec.ts) | 可参考正常／无效证明向量，不是生产厂商事故记录；引入时固定版本和许可证 |
| [原项目 PI 接入评估](https://github.com/hankesong/hankesong/blob/main/docs/pi-integration.md) | 复用工具适配建议；本仓库没有 PI 子模块或已完成的模型接入 |

赛事背景参考原项目整理的 2026-10-05 手册快照及 [赛道说明](https://github.com/hankesong/hankesong/blob/main/docs/tracks.md)。本次未重新核实最新报名、评审、提交及部署通知，不将历史材料写成当前资格保证。

## 5. 正式开发的首批验证项目

固定基准与真实账户证明能否完整核验；提供商查询窗口；服务签名与密钥历史；规范化及负例；证据获取和第二实例复验；链配置、注册表 ABI 与实际费用。性能、误报率、独立复验一致性均需用实际运行结果填写。

方案融合发布完成的是术语和优先级统一、图文同步及来源整理，不等于这些工程项目完成。后续用户已要求正式开发，见 [003](decisions/003-development-kickoff.md)；按 [启动清单](10-开发启动清单.md) 逐项取得运行证据。

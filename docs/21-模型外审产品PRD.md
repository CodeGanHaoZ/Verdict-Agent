# Verdict Guard 产品 PRD —— 模型外审与协同防御

v0.1 · 2026-10-07 · 产品化设计稿（待评审）

配套：[主 PRD](02-PRD.md) · [PI 直接执行](15-PI接入与复验.md) · [红队攻击测试](19-红队攻击测试.md) · [Guard 实现记录](20-Verdict-Guard.md)

## 0. 定位与状态

**Verdict Guard 是执行 Agent 的模型外审与协同防御层：一个独立的「外审模型」在执行 Agent 的每个动作落地前审看其行为是否越出锁定边界，异常即停；停止与放行由确定性守护执行；攻击特征固化为可签名、可复验、可广播的证据与版本化规则，供其他 Agent 实例提前布防。**

与主 PRD 的分工一句话讲清：主 PRD 的验收内核是**数据外审**（交付的数据对不对），本文的 Guard 是**行为外审**（模型在干什么、该不该停）。两者共享同一套纪律：三态结果、证据可复验、归因不归责、模型不替代确定性代码。

状态说明：外审内核已在 [20-Verdict-Guard](20-Verdict-Guard.md) 实现（独立审查器、硬规则先行、一次性许可、Ed25519 签名报告、双模型真实联调）；[19-红队](19-红队攻击测试.md) 复现了一个首次绑定范围缺口。**本文不重做内核，只补四个产品化增量**（§5 P0），并把实现记录上升为可验收的产品需求。P0/P1/P2 表示交付优先级，不表示已实现。

## 1. 用户、问题与产品目标

| 用户面对的情况 | 系统应如何帮助 | 首版边界 |
| --- | --- | --- |
| 执行 Agent 中途被提示注入／数据污染，行为越出任务范围（红队已复现：换账户、扩次数、扩候选、换区块） | 外审在动作执行前拦截，越界动作不获得许可 | 首版覆盖「范围类」与「循环／预算类」攻击，不宣称抵御任意注入 |
| 一次攻击得手后，其他 Agent 实例毫不知情 | 攻击报告 Ed25519 签名、化名化导出、跨实例导入复验 | 首版只做实例间交换与本地公共索引；主网写入按授权单列 |
| 同类攻击再次出现，每次都要靠模型现场判断 | 规则增强：确认的攻击特征固化为版本化规则，导入后本地先行拦截、不再调模型 | 规则限四类固定枚举（范围扩张），不接受代码规则 |
| 正常任务被外审误拦 | 误拦单独计数、输入补全后放行、对照正常样本 | 不承诺零误报（已保留 run-4gGiVo 误拦记录） |
| 外审模型不可用／被拖慢（已实测 run-U4xnlv 无权限、同模型监督预算耗尽） | 显式策略分支：fail-open（继续并标 UNAUDITED）或 fail-closed（挂起等待） | 默认值是策略选择，不是安全证明；绝不把超时记成攻击 |

成功标准：**越界动作拿不到一次性许可；每一次拒绝都能导出一份他人可复验的报告；同类攻击第二次出现时不再依赖模型。**

## 2. 角色与信任边界

| 角色 | 是谁 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 执行模型（前方） | PI 直接执行实例（现 GLM-5.3，plan/v2） | 按任务发起工具调用 | 不能给自己放行；不能改写 A 验收结论 |
| 外审模型（后方） | 独立 PI 实例＋独立会话／凭据（默认异构：deepseek-v4.1-flash；可切同模 GLM-5.3，须标注同源盲点） | 只读活动窗口、提交结构化决定 | **没有任何写工具**；不能直接执行停止；不能覆盖硬规则；输出不合 schema 即丢弃 |
| 确定性守护 | Guard 硬规则＋一次性许可＋SQLite 事务 | 唯一的停止／放行执行者 | 停止不撤销已验收结果；不因模型失败伪造结论 |
| 任务委托人 | 宿主／操作者 | 以结构化 AgentConditions 锁定账户、区块、字段、候选、预算 | 约束绑定后不可变；不可信引用中的值不能成为约束 |

外审模型被注入的最坏后果是「错误地拒绝或放行某次动作」，不是获得执行能力——这是「后方模型没有写工具」这一设计买到的保证。

## 3. 核心用户流程

1. 委托人以结构化 AgentConditions 锁定本次任务（修复红队缺口：绑定前先锁，PI 的 `start_task` 必须与锁定约束逐字段比对，不再依赖全文正则与系统提示词）。
2. 执行 Agent 运行；每个顺序工具在业务执行前 hook 至外审等待审查。
3. 硬规则先行（毫秒级，不调模型）：账户／区块／候选／预算越界、当前任务状态、证据归属、复验目标。
4. 外审模型按窗口审看最近活动（动作序号、工具、参数／结果摘要、A 验收 verdict、已花费 wei），输出结构化决定。
5. 守护原子发放一次性许可或拒绝；SQLite 事务再次检查取消、边界与参数摘要。
6. DENY → 停止后续动作（复用既有 stop 语义），保留证据；安全报告 Ed25519 签名、默认化名化导出。
7. **暴露到网络**：签名报告发布到本地公共索引；ERC-8004 feedback 适配（P1，如实标注部署状态）。暴露的是攻击特征（工具、参数摘要、目标范围、注入模板哈希），不含 prompt 原文与隐私。
8. 其他实例导入：重算摘要、独立验签、复验范围越界 → 生成候选规则。
9. 维护者启用规则（ruleVersion+1）→ 同类攻击本地先行拦截、不再调模型；页面对照启用／停用规则的拦截差异。

## 4. 结果模型

主结果 `ReviewDecision`：**ALLOW / DENY / ESCALATE**。内部同时保存：`ruleMatched`、`modelFinding`、`stopAuthority`（rule ｜ model+policy ｜ operator）、`reasonCodes`（SCOPE_EXPANSION、LOOP_DETECTED、BUDGET_ANOMALY、INJECTION_SUSPECTED、AUDITOR_UNAVAILABLE、UNREPLAYABLE…）、`auditIntegrity`。

纪律沿用主 PRD：DENY 不等于对该 Agent 的定罪，只是本次动作未获许可；模型超时不记为攻击；导入报告不采用其自报结论；AUDITOR_UNAVAILABLE 下的放行必须携带 UNAUDITED 标注供下游感知。

## 6. 技术选型

| 项 | 选择 | 理由与备注 |
| --- | --- | --- |
| 外审运行时 | `@earendil-works/pi-agent-core` + `pi-ai`（主工程已用 1.0.4 跑通） | 双实例独立会话／凭据；外审实例工具白名单只有只读与 `submit_review`，无写工具 |
| 执行模型 | GLM-5.3（modelarts plan/v2，compat=glm，已实测） | 沿用 15 号文档配置；`VERDICT_PI_*` 环境变量 |
| 外审模型 | 默认 deepseek-v4.1-flash（openai/v1，已实测 200）；可切 GLM-5.3 同模 | 异构降低同模型共同盲点；同模为用户已选方案，报告须标注；qwen3-32b 目录可见但 403，不采用 |
| 活动交换格式 | **pi-telemetry typed schema** | vendor-neutral；「暴露 Agent 活动的插件」以它为接入标准，不另造协议（FR-G02） |
| 规则引擎 | 四类固定枚举 + JSON 参数，随 guard:rules CLI 管理 | 沿用 20 的安全决策：不接受代码规则；启用／撤销走独占数据库锁 |
| 报告签名 | Ed25519（reporterId + trustedReporters 本地信任配置） | 沿用 20；信任名单只能来自本地配置 |
| 事件传输 | 进程内 hook + HTTP 轮询（P0）；SSE（P1） | 与主工程轮询纪律一致 |
| 存储 | SQLite 双库（业务库＋报告库），独立实例独立目录 | 沿用 20；第二实例独立验签重算 |
| 前端 | 原生 HTML/CSS/JS 三视图 | 与现有两套页面同栈 |
| 明确不做 | 自动反击、资金处置、prompt 原文入报告、任意代码规则 | 主 PRD 纪律延伸 |

## 7. 产品设计（三个主视图）

| 视图 | 用户应看到 | 必须处理的分支 |
| --- | --- | --- |
| ① 外审监控台 | 受监 runs、外审状态灯（ALLOW/DENY/UNAUDITED）、审查等待耗时（20 已记录该指标）、策略开关（fail-open/closed）、模型配置与用量 | 外审模型未配置／超时／无权限如实显示；UNAUDITED 放行可见 |
| ② 审计时间线 | 执行事件流（序号、工具、参数摘要、A verdict）＋外审决定点＋一次性许可消费点；启用／停用规则的对照 | 硬规则拦截与模型拦截分色标注；DENY 的报告可一键导出 |
| ③ 威胁账本 | 签名报告列表、导入／复验状态（含 UNREPLAYABLE）、候选规则→启用（ruleVersion 演进）、广播状态（本地索引／ERC-8004 未接入） | 篡改报告导入失败可见；规则撤销后相关规则失效可见 |

叙事皮（可选，沿用「页面术语不变，只换旁白」纪律）：**黄鹤楼·瞭望哨与烽火**。黄鹤楼始建于三国吴黄武二年（223 年），原为军事瞭望楼——瞭望哨发现敌情（外审发现越界），烽火台举火（把攻击特征广播到网络），各关隘按烽火增强戒备（规则增强后本地先拦）。与茶港皮互补：**茶港管数据验收，鹤哨管行为外审**，两个武汉地标正好各管一层。

## 8. 非功能要求

- **延迟**：硬规则路径本地 P95 ≤ 100ms；审查等待单独计时（TEST_TRANSPORT 的 9.8ms 均值不得用于估计真实模型延迟）；外审超时沿用 18 号文档的预算与降级语义。
- **安全**：外审输入以摘要与关系为主，不传 prompt 原文与隐藏思考；活动流中的外部文本须转义／摘要化后才进入外审上下文（外审自身也是注入面）。
- **隐私**：报告默认化名化（账户、区块、候选替换为化名，预算转大小关系）；显式公开材料须 `acknowledgePublic` 且不含已知凭据。
- **确定性**：同一报告＋同一可信配置复验结果一致；语义型事件无原始材料时返回 UNREPLAYABLE，不声称复现。
- **发布隔离**：本地处置结论与广播状态分别保存；广播失败不改写 DENY/ALLOW。

## 9. 完成标准与负例

| 编号 | 场景 | 期望行为 |
| --- | --- | --- |
| AC-G01 | 正常替换任务（错块→错值→PASS）全程外审 | 全部 ALLOW，任务 COMPLETED，仅采用通过数据（对照 run-o24i2s） |
| AC-G02 | 红队四例受控范围扩张（换账户/扩次数/扩候选/换区块） | 全部被后端在绑定前拒绝；先修 FR-G01 再测，不允许假装通过 |
| AC-G03 | 注入剧本触发越界动作 | 硬规则或外审 DENY → 停止执行，证据与报告保留 |
| AC-G04 | 外审模型超时／无权限／预算耗尽（对照 run-U4xnlv、run-xej66M） | 按策略分支执行；不记为攻击、不伪称已审、不自动扩预算 |
| AC-G05 | 模型 DENY 但硬规则未命中 | stopAuthority=model+policy；报告标注「模型建议」，不写成已证实攻击 |
| AC-G06 | 篡改报告或未知签名者导入 | 摘要／验签失败，不生成规则，不沿用其结论 |
| AC-G07 | 语义型事件无原始材料复验 | UNREPLAYABLE，不得声称复现 |
| AC-G08 | 误拦正常候选（对照 run-4gGiVo） | 输入补全后放行；误拦单独计数，不放大数据边界 |
| AC-G09 | 规则启用后同类攻击重放 | 本地硬规则先行拦截，不调模型；停用规则后拦截消失（页面可对照） |
| AC-G10 | 规则撤销 | 相关规则失效，历史报告保留原版本与时间 |

## 10. 推进顺序与交付

**FR-G01（约束锁定修复）→ FR-G02（telemetry 适配）→ FR-G04（广播）→ FR-G05（规则生效）→ FR-G07（三视图）**。FR-G01 是红队确认的已知缺口，必须最先做；在它修复前，不得在任何材料中宣称「已具备提示注入防护」。

演示主线（3 分钟）：正常任务放行 → 受控注入越界被拒（展示报告签名导出）→ 第二实例导入报告、启用规则 → 同类攻击本地先拦（不调模型）→ 停用规则对照拦截消失。负例必演：外审模型超时的策略分支。

交付清单：约束锁定回归（含红队四例）、telemetry 适配器与示例插件、签名报告公共索引页、规则版本演进记录、三视图页面、演示脚本与运行说明。主网/ERC-8004 写入未完成则如实标注，不影响本地闭环。

## 11. 开放问题

1. fail-open / fail-closed 的默认值：建议高危动作清单（转账、签名、删除类）fail-closed，其余 fail-open——待评审。
2. 同模型监督（GLM-5.3 双侧）的价值边界：已实测同模监督存在预算耗尽致任务中止（run-xej66M），同源盲点风险须在报告与页面持续标注。
3. 「暴露到某个网络」的主网授权：ERC-8004 feedback 写入涉及费用与身份注册，按主 PRD 独立授权线处理。
4. 误报率度量：需要固定正常样本集（≥20 条）作为对照基线，当前样本量不足以外推。

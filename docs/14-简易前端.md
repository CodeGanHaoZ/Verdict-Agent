# 简易前端与底层编排

用户在 B 合并后要求添加简易前端，并询问底层 Agent 框架。此次实现网页操作层，范围不扩展到模型或链上部署。

## 实际框架

底层目前**没有接入专门的 Agent 框架或大模型**。运行流程是项目自建的 Node.js / TypeScript 确定性编排器（`apps/server/src/engine.ts`）：选择候选、发起交付、调用 A 内核、预算内替换、保存证据、独立复验。

`@verdict/core` 负责密码学和请求条件检查，`@verdict/evidence` 负责材料规范化／摘要／复验，`@verdict/observations` 负责真实端点观测，SQLite 保存状态。PI 是后续计划，当前没有 PI、模型推理或自主规划循环；“Agent”名称不能被解读为已经接入 LLM。

前端使用 TypeScript + Vite，不额外引入 UI 框架，通过既有 API 和共享 schema 展示结果。将来如果接入 PI 等宿主编排，应调用同一套服务接口，不能改变确定性核验标准。

## 使用

```bash
# Node 22.23.3，仓库根目录
npm ci --ignore-scripts
npm run dev:init
npm run dev:start
npm run web
```

访问 http://127.0.0.1:5173 。三个入口：

- **任务验收**：账户／区块、字段、调用方案、预算和历史证据开关；实际调用时间线、逐项约定与交付检查；只有被采用结果显示事实卡。
- **服务目录**：声明能力与实测分开，展示采样来源、范围、窗口、次数与限制；按钮触发真实 RPC 观测。
- **证据复验**：选择记录，下载原始证据／manifest，读取独立完整性与发布状态；第二实例重算并显示结果；固定请求比较历史证据开关前后的选择顺序。

提交未确认时保存原请求供幂等重试，不重新生成任务 ID；提交新任务会立即清除上一任务的事实卡。轮询中断时停止新提交，重新连接后查询同一任务。证据文本都作为数据展示，不执行材料中的指令。

前端终端 Ctrl-C 停止；后端用 `npm run dev:stop`。`npm run web:preview` 预览构建产物，仍需要独立后端。

## 实际验证与待接力

类型检查、生产构建、原有 A/B 70 项检查，以及 5 条真实浏览器端到端测试。浏览器测试验证签名错误替换、全失败停止、原文件下载、独立复验与排序、断网响应重试、刷新恢复及窄屏。浏览器记录和本机预览保存在忽略目录，不作为开源固定证据提交。

C 的简易三个视图已接入真实 API；**真实存证 adapter、合约／交易、钱包、公开部署与完整赛事演示材料仍未完成**。也没有模型聊天、文件上传导入界面或完整历史任务搜索。默认发布为 `not_requested`，复验 COMPLETED 与数据 PASS 始终分开。

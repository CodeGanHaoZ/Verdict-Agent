## 2. 依赖方向

箭头表示“左边允许依赖右边”。这是本地包边界，外部库仍需兼容性与许可证检查。

```text
core ───────────────→ protocol
evidence ───────────→ core + protocol
observations ───────→ protocol
anchor-client ──────→ protocol

server ─────────────→ core + evidence + observations + protocol
  待 C 接入时增加 anchor-client
verifier-cli ───────→ evidence + core + protocol
web ────────────────→ protocol + server 的 HTTP API
demo services ──────→ protocol + core（公开签名摘要 helper）+ viem 签名库
consumer example ───→ server API / 最小宿主接口
```

`protocol` 是协议定义，不实现密码学验签；它提供可共享的签名结构与域定义，B 的演示服务据此签署，A 的 core 验证。`evidence` 可以调用 core 重验，core 不反向导入 evidence，避免循环依赖。

网页不导入 server、数据库或含密钥的发布实现。CLI 从文件加载材料和可信配置，不通过“请求 server 返回旧 verdict”的方式实现复验。Solidity 合约独立构建，不依赖 TypeScript 运行时；合约 ABI 由 C 输出给 anchor-client，链配置由 B 管理。

## 3. 一个模块内部如何组织

首次实现时从少量真实文件开始，不为每个概念创建空层。以下是有代码后可采用的布局：

| 模块 | 首批源码职责 | 不放在这里 |
| --- | --- | --- |
| protocol | request、delivery、verification、evidence、run 的 schema，枚举，公开入口 | 网络、DB、验签执行、私钥 |
| core | context／header、signature、account-proof、fields、verdict | HTTP 路由、模型解释、存证 |
| evidence | canonical、hash、bundle、fact-key、replay | 全局数据库、页面、网络抓取 |
| server | routes、orchestration、selection、repositories、publish-queue | 另一套证明算法或字段判定 |
| web | services、audit、evidence 三个页面；API client 和展示组件 | 复制验收算法、后台密钥 |
| observations | 固定端点适配、超时／限流归一化、指标窗口 | 无依据的全局声誉总分 |
| anchor-client | 目标配置、发布调用、确认读取、receipt | 自动决定本次数据是否正确 |

应用层组装依赖；领域包保留清晰输入输出。只有实际复用出现时再抽公共 helper，避免建立无人维护的通用 `utils` 大包。

## 4. 数据与配置位置

公开、经审阅的测试向量进入 `fixtures/core/`，同时保存来源、许可、链／区块／对象、采集或生成方式、预期结论与规则版本。没有全部材料时不标“可复验”。

页面形状样本进入 `fixtures/ui/`，必须带 UI_MOCK。实际执行的故障注入可以使用真实证明，但必须标 FAULT_INJECTION；不能与未执行的页面样本混为一类。

`config/` 只保留模板和公开策略，运行时由 `--config` 加载 JSON，`.env.example` 仅记录代理环境提示。真实端点凭据、演示私钥、数据库和原始日志均放 `.local/`；B 为第一／第二实例提供隔离目录。证据上传仓库或进入公共索引前分别审阅，不能直接把整个运行目录提交。

## 5. 协作规则的层级

根 `AGENTS.md` 保存稳定的范围、分工和证据底线。重要模块的 `AGENTS.md` 只补充该模块的输入输出、依赖限制与验证要求；README 保存模块用途、实现状态和实际存在的命令。不要在多处复制整份 PRD。

从根目录修改子模块时，主动阅读该子模块的规则；不要假设所有嵌套规则都已自动载入。本项目采用标准 `AGENTS.md` 文件名，不另建内容易漂移的 `Agent.md` 副本。文件发现机制参考 [OpenAI Docs](https://developers.openai.com/codex/guides/agents-md)。

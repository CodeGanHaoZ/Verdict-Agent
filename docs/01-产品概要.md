## 一句话定位

**Verdict 是 Agent 服务的验收与证据审计层：核对服务承诺与实际交付，给出逐项依据和下一步处理，并把记录留给后来的调用者复验。**

首个场景是以太坊指定区块的账户状态，包括原生币余额、nonce 和 codeHash。产品面向研究、索引等需要链上状态的 Agent 开发者，也为服务方与调查人员提供逐项可解释的交付记录。

## 用户遇到的问题

服务身份已经登记、过去获得好评、HTTP 请求成功，都不能单独回答「这次返回的数据是否符合我的要求」。常见情况包括目标区块不匹配、响应字段与状态证明矛盾、历史证明不受支持、请求被限流，以及缺少足以核验或确认来源的材料。

开发者目前往往要自己处理服务切换、证明校验和错误说明；其他使用者也难以重用一条包含完整条件的失败记录。Verdict 将这些步骤组织成同一条可复验流程。首版验证范围有限，不承诺覆盖行情准确性、任意模型回答或完整合约安全性。

## 核心使用故事

研究 Agent 为某个合约生成指定区块的状态事实卡。它先写明网络、账户、字段、区块哈希、签名要求和调用预算。

目录按能力、适用证据及本地观测给出候选顺序。演示服务 A 签署了错误区块的数据，服务 B 签署的余额与有效证明矛盾，两者都被拒收；服务 C 交付通过，数据才进入事实卡。真实公共 RPC 的限流或证明范围限制单独展示为有来源的观测。

第二实例下载记录并重跑检查，在证据仍适用时调整候选顺序。所有候选均未满足要求时，系统停止该数据依赖并说明原因。A/B/C 是明确标注的受控演示服务，不能冒充真实厂商事故。

## 四项核心机制

1. **按任务验收。** 请求固定网络、账户、字段和目标区块；正确的历史数据不会仅因区块较旧被拒收。
2. **数据核验与交付归属分开。** 状态证明支持数据检查，签名和密钥绑定支持来源归属；缺少签名不自动说明数据错误。
3. **证据可以重新执行检查。** 完整材料、规则版本和信任前提随包保存，消费者重新验算，不只读取上一份报告的结论。
4. **经验影响选择，当前结果决定采用。** 展示多维指标与简单排序；没有历史的新服务仍可尝试，历史好评不能绕过本次验收。

## 审计报告应当回答什么

每条记录围绕「哪个服务、在什么条件下、承诺什么、实际交付什么、为什么接受或拒收」展开。报告按条展示承诺、交付、证据引用、执行的检查、未覆盖内容和后续动作。

例如，服务承诺查询区块 X，却签署区块 Y 的状态；即使 Y 的证明有效，这次交付仍未满足要求。系统应展示两个区块及签名依据，然后换服务。若只有调用者日志、没有服务签名，则保留数据不符的发现，同时说明交付归属尚未证明。

这套审计方法可以作为更广泛安全助手的数据与证据模块。DAO 承诺审查、升级／审计覆盖检查和反事实调查仍属于候选应用，分别需要专用证据与验证方法，不列为本稿已具备的功能。

## AI 与区块链各自的作用

AI 可以将用户需求转成结构化任务、在允许的工具与预算内选择下一步，并解释证据。判定、数字、签名和证明检查交给确定性代码。模型接入尚未完成；轻量脚本演示不能被称为已完成的自主 Agent。

以太坊提供首个可核验的状态数据场景；ERC-8004 是拟接入的公开身份和记录关联机制，具体部署与 ABI 需验证。BOT Chain 是拟议的证据摘要锚定目标，便于不同主体引用同一份材料。链上记录不能替代内容核验、文件可用性或独立身份判断。

公共价值来自开放的验收规则、证据格式、故障样本和复验工具，以及服务修复后可重新验证的记录机制。

## 建议首版范围

| 必须形成的闭环 | 计划交付 |
| --- | --- |
| 明确需求与选择服务 | 任务约束、能力目录、小规模真实观测、多维指标和简单排序 |
| 验收交付 | 固定区块基准、账户证明、字段比对、服务签名及三态结果 |
| 处理失败 | 三个签名演示服务、预算内替换、全部失败时停止依赖 |
| 复用证据 | 规范化证据包、轻量索引、第二实例复验、排序前后对照 |
| 提供入口 | 最小调用接口、三个网页视图、复验 CLI 的拟议接口 |
| 准备存证 | 本地／测试环境验证设计、异步发布状态与主网材料清单 |

PI、完整 SDK/MCP 分发、支付、复杂信誉与抗女巫聚合后置。BOT 主网部署与 ERC-8004 写入属于单独工作线，需要具体网络、费用和授权；不阻塞核心验收流程。

## 结果与能力边界

页面显示本次请求的 `PASS / FAIL / UNVERIFIABLE`，同时解释数据检查、签名归属与具体原因。限流使用 `RATE_LIMITED`，明确的能力缺失使用 `UNSUPPORTED`；它们不是自动归责的公共差评。

系统不以确认人数加权，不宣称已解决女巫攻击；也不通过一条签名错误交付判定服务方动机。修复后的新交付可以通过，旧证据保留原来的版本、时间和任务范围。

所有上述产品能力仍是计划。反事实清算调查保留为备选场景，未并入首版范围。完整验收清单见 [PRD](02-PRD.md)。

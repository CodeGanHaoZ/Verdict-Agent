# 工作包 B：服务接入、任务流程与后端

交接状态：已进入正式开发，岗位待认领，业务实现待完成。与 [根规则](../../AGENTS.md)、[工程结构](../09-工程结构.md)、[三人分工](../07-三人分工.md)、[接口约定](../08-接口约定.md)、[PRD](../02-PRD.md) 一起阅读。

## 你的交付目标

把一次任务跑成完整流程：选择服务、获取交付、调用 A 的内核、失败替换、合格后采用、保存证据。第二实例能独立复验并改变下一次选择。你兼任联调负责人。

## 按顺序做

1. 沿用已合入 main 的 Node 22.23.3／npm 10.9.9、TypeScript workspace、共享 schema 与 package-lock.json；补入 B 的包和实际启动入口。与 C 对齐业务对象及 HTTP 路由，不重新初始化根工程；接入真实内核前的 API 样本明确标为 UI_MOCK。
2. 用 A 的签名格式实现 `demo-wrong-block`、`demo-wrong-value`、`demo-valid` 三个演示服务。运行时生成本地演示密钥，配置其可信绑定；不写入真实凭据，不冒充底层 RPC 提供商。
3. 做少量真实公共 RPC 观测，记录来源、时间、方法、范围、限流／超时／不支持和延迟。能力声明、实际观测、冻结样本与人工故障分别存储。
4. 实现目录、多维指标和简单排序：硬条件 → 适用证据 → 本地观测 → 同等条件下的成本／延迟。证据须先复验；未知不算支持，重复事实不加权。
5. 实现有预算的调用循环。每份交付都调用 A 的内核；只有满足本次要求的数据才能进入事实卡，候选耗尽或预算用完就停止依赖。
6. 建立 SQLite 索引与内容寻址证据存储，提供任务、候选、证据下载及复验 API。`report_outcome` 重验材料，拒绝调用者自报结果和 UI_MOCK 进入公共索引。
7. 提供第二实例的独立端口、数据库、证据目录和信任配置，通过 A 的核心／CLI 重验导入材料；准备固定其他输入、只开关历史证据的排序对照。
8. 接入 C 的存证适配器与独立发布状态。先以 not_requested 运行；本地验证或获授权的网络才触发发布。实现重试／幂等边界，发布失败不修改验收结果。
9. 提供一个最小调用方示例及全队启动／复现说明。宿主工具循环跑通后，模型或 PI 接入才作为 P1，不让它阻塞核心流程。

## 完成标准

- 三个服务可触发错块、错值和正常路径，自动替换后采用真实通过的数据；全部失败和预算耗尽时停止，对应 AC-07。
- 不支持、429、超时分别记录；至少有来源明确的真实观测或明确的未完成说明，对应 AC-06、AC-12。
- 索引不把重复转发增加为信誉优势；新交付修复后可通过，对应 AC-11。
- 第二实例不读取第一实例 DB，重新检查证据后，在固定输入下展示排序或复检理由变化，对应 AC-08、AC-10。
- C 的页面无需硬编码结论；发布失败与任务结果分别可见，对应 AC-13。

不做完整服务市场、支付托管、复杂信誉聚合或多 Agent 架构。先用少量候选做出可信流程，再扩展数量。

# 工作包 A：验收内核、证据格式与复验工具

交接状态：已进入正式开发，岗位待认领，业务实现待完成。与 [根规则](../../AGENTS.md)、[工程结构](../09-工程结构.md)、[三人分工](../07-三人分工.md)、[接口约定](../08-接口约定.md)、[PRD](../02-PRD.md) 一起阅读。

## 你的交付目标

输入结构化请求、服务响应和独立验证上下文，输出有逐项证据的验收结论。别人拿到完整材料，在另一个进程中能重新执行检查。你是共享 schema 与验收规则负责人。

## 按顺序做

1. 定义并导出 TaskSpec、DeliveryEnvelope、VerificationResult、CheckResult、EvidenceBundle 的 schema、枚举及初始原因码，B/C 共同确认接口。
2. 选一个来源明确的真实账户状态样本：固定链与区块哈希、区块头、stateRoot、accountProof、账户值。先验证正常路径，再验证错块、错值、无效证明和账户不存在的负例。
3. 实现 EIP-712 验签与可信密钥映射核验，统一签名 payload／domain 构造函数供 B 的演示服务使用；覆盖改响应、错误请求绑定、签名缺失、有效期和重放边界。
4. 生成“承诺／实际交付／检查／依据／结果”审计行，分别输出数据结论和交付归属；缺证据、规则未知、基准冲突不能变成 PASS。
5. 固定规范化规则，输出不含自身哈希的证据正文与外围 manifest；提供事实分组键，供 B 去重和判断适用性。
6. 实现拟议的 `z-verify <bundle>` CLI：读取文件、校验摘要、重跑检查，输出可读报告与 JSON。复验上下文由本地可信配置提供，不自动相信包内密钥声明。
7. 交付正常、错块、错值、篡改、无签名、缺材料和未知规则等实际运行用例；说明固定依赖与离线可复验边界。

## 完成标准

- PRD AC-01～05 通过，AC-06 中基准冲突与材料缺失正确返回未知；B 的流程可以直接调用，不需要改写你的结论。
- 对同一真实包，在不读取第一实例数据库的独立进程重跑，逐项结果一致；对应 AC-08。
- 包改动、规则不支持或必要材料缺失时，AC-09 显示完整性失败或无法复验；改包后重新算哈希也不能绕过签名／证明检查。
- 证据完整性与数据真假、签名归属分开；规则版本、信任前提和检查覆盖能解释清楚。

先保住真实基准、证明、签名与完整复验，不扩展任意存储槽、DAO 模拟、完整合约审计或反事实实验。P0 不需要你实现网页、API、Agent 编排或主网部署。

# 工作包 C：审计界面、存证与演示

交接状态：待认领、待实施。与 [三人分工](../07-三人分工.md)、[接口约定](../08-接口约定.md)、[交互图](../04-交互设计图.svg) 一起阅读。

## 你的交付目标

让使用者看得懂一次任务的约定、实际交付、验收依据与下一步动作；能下载材料并看到第二实例复验。你兼任演示与交付负责人，负责最小存证合约及适配器的本地验证。

## 按顺序做

1. 对齐共享字段与 API，用明确标为 UI_MOCK 的数据搭好三个视图，不等待全部后端完成。
2. **选择服务视图**：任务条件、候选能力、来源、窗口／样本数、多维指标及排序理由；显示未测、限流、不支持和无候选。
3. **单次审计视图**：调用与替换时间线、承诺—交付—证据—结论—处置对照、数据结论与服务归属、未知／未覆盖项。通过后才显示事实卡，全部失败时明确停止。
4. **证据与复验视图**：证据下载、规则版本和适用范围、独立实例重算的结果／差异、启用／停用历史证据时的排序变化、独立的发布状态。
5. G2 接 B 的真实 API，逐步移除演示 mock；既有样本可以保留为离线展示，但入口与标签必须明确。
6. 实现最小摘要存证合约与 `publish_anchor` 适配器，在本地链验证提交、事件、重复提交策略与失败处理。记录发布者、摘要和 schemaVersion；不能覆盖其他发布者的记录，不在合约内伪称已核验 verdict。
7. 给 B 明确的 AnchorReceipt；默认不自动发起网络交易。本地确认要标明本地网络，不能当成 BOT 主网部署。主网网络、ABI、Gas 与费用授权具备后才进入独立部署工作线。
8. 整理一条演示流程：错块拒收 → 错值拒收 → 正常通过 → 展开依据 → 下载 → 第二实例复验 → 选择变化；补全失败、未知、篡改和锚定失败分支。
9. 整理运行入口、README、演示材料、来源和能力边界。只有实际完成的功能才写进已实现清单。

## 完成标准

- 页面完整呈现 PASS／FAIL／UNVERIFIABLE、数据／归属、原因与证据引用，不把链上 confirmed 当作验收通过。
- 正常路径、所有候选失败、基准冲突、无签名、429、证据篡改／不可取／规则未知均有正确展示。
- “复验完成”不自动显示绿色 PASS；展示实际重算结果、差异及对当前任务的适用性。
- 下载的是 B 保存、A 生成的原证据；界面中可看到第二实例和排序变化，不用静态文字冒充运行。
- 本地存证事件与 evidenceHash 一致；发布失败不改变已有验收结果，且实际网络清楚可见，对应 AC-13。
- 演示可以从干净启动状态重走；冻结回放与实时执行分别标识，说明哪些功能仍未实现。

不做一张统一“安全总分”大屏，不接入支付／托管，不把其他候选审计场景做进首版页面。ERC-8004 适配是后续工作，不为展示名称伪造注册身份。

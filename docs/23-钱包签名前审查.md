# 钱包签名前审查（首版）

当前版本增加了一个由网页发起的浏览器钱包入口：交易参数先提交到后端，服务器做确定性边界检查和 RPC 预执行，随后由独立 PI 审查器读取实际检查结果。只有 `ALLOW`、参数摘要未变化、短时许可未过期且再次状态检查通过，网页才调用钱包的 `eth_sendTransaction`。

## 已实现

- EIP-6963 与 legacy injected provider 发现；不读取私钥或助记词。
- 绑定账户、链、收款人、金额和费用上限；请求 ID 与交易摘要幂等。
- 后端限制 RPC 目标来自本地环境变量 `VERDICT_WALLET_RPC_URL`，只接受 HTTPS 或 loopback HTTP；不接受浏览器传入的 RPC 地址。
- 服务器检查 `eth_chainId`、账户／收款人代码、nonce、余额、base fee、`eth_call`、`eth_estimateGas`，并在检查前后比较区块摘要。
- PI 只能按顺序读取 `inspect_transaction`、`check_policy`、`simulate_transaction`，再提交带实际检查引用的 `ALLOW/BLOCK/UNCERTAIN`。
- 一次性、短时消费许可；账户、链、参数、nonce、余额或区块变化都会要求重新审查。服务器永不签名或广播。
- 审查过程、检查结果和 `NOT_BROADCAST_BY_SERVER` 状态可查询，页面展示模型来源与限制。

## 配置与运行

初始化会在 `.local/b-demo/local-one.json` 和 `local-two.json` 增加 `wallet` 段。设置本地 RPC 和独立审查模型环境变量后重启后端：

```sh
npm run dev:init -- .local/botchain-testnet
npm run wallet:configure-network -- .local/botchain-testnet/local-one.json bot-testnet
export VERDICT_WALLET_RPC_URL=https://rpc.bohr.life
# 还需要按 docs/20-Verdict-Guard.md 配置 VERDICT_GUARD_API_KEY
npm run server -- --config .local/botchain-testnet/local-one.json
npm run web
```

BOT Chain 测试网参数：chainId `968`（`0x3c8`），RPC `https://rpc.bohr.life`，测试币 Faucet 为 `https://faucet.botchain.ai/basic`，浏览器为 `https://scan.bohr.life/`。`https://rpc.botchain.ai` 是 chainId `677` 的主网，不能用于这个测试实例。`wallet:configure-network` 只允许修改 `.local/` 下的本地配置，不读取或写入秘密。

打开网页的“钱包审查”页，连接 MetaMask、Rabby 或其他支持注入 provider 的钱包。后端配置的 chainId 和 RPC 必须与钱包一致。

## API

- `GET /api/wallet/meta`：配置状态和允许的网络。
- `POST /api/wallet/reviews`：创建审查。请求包含 `clientRequestId`、`transaction` 和明确 `intent`。
- `GET /api/wallet/reviews/:reviewId`：轮询检查、PI 事件和决定。
- `POST /api/wallet/reviews/:reviewId/consume`：由网页在签名前消费一次性许可；交易参数必须逐字段一致。
- `POST /api/wallet/reviews/:reviewId/cancel`：停止审查。

## 当前边界

首版只允许无代码账户之间的普通原生币转账，且只作交易前检查。ERC-20 授权、`permit`、合约调用、批量交易、复杂 calldata、资产变化模拟、MEV／重组、硬件钱包细节和第三方 DApp 交易尚未覆盖；这些请求会停止或标记为未知。`eth_call` 与估算成功不是未来状态保证，也不是合约安全审计。连接钱包并不等于已经广播交易；网页显示的钱包返回哈希仍需另行确认链上状态。

测试网或主网 RPC、钱包连接与任何实际交易广播都需要操作者自行授权。钱包接口与既有账户交付验收、证据发布和链上存证分开，不能把预审查结果写成 A 包验收 PASS。

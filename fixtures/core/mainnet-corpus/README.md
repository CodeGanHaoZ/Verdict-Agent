## 来源与信任边界

证明由 `https://eth.drpc.org` 的 `eth_getProof` 返回；1200 万／1400 万区块头另与 `https://1rpc.io/eth` 核对，其他区块另与 `https://ethereum-rpc.publicnode.com` 核对。每次请求固定高度／哈希，读取完成后检查同高度哈希未改变。

账户记录来源是公开账本事实；没有复制厂商源码、使用记录或身份签名。零地址、高 nonce 和零 ETH 余额标签描述的是该区块下的实际状态，不推断地址控制者。合约的账户证明不证明任意合约业务语义或代币余额。

双端点头部一致不证明它们运营主体独立，也不替代共识／最终性验证。测试使用调用者接受的固定检查点；完整核验时生成本地临时适配器签名，不能冒称 RPC 厂商签名。

本轮未修改生产核验规则来适配样本。全部 8 条记录经过既有 `verify_delivery`，结果均为 PASS；文件摘要和具体预期值另由回归测试检查。

## 运行

在固定 Node/npm 环境中，仓库根执行：

```bash
npm run typecheck
npm test
```

`packages/core/test/corpus.test.ts` 覆盖 8 条真实正例、快照完整性，以及两个明确标注为人工组合的负例：把另一个真实区块的有效证明混进当前响应、把同区块另一个账户的有效证明混进当前响应。这些负例均被拒收，不是实际服务事故。

原有 37 项加新增 11 项，当前 **48 项通过，0 失败，0 跳过**。运行测试无需 RPC 网络。

重新采集旧块样本时，可显式选择历史头部来源与账户：

```bash
npm run capture:proof -- --block 0xd59f80 --baseline-source https://1rpc.io/eth --account 0xc02aaa39b223fe8d0a0e5c4f27ead9083c756cc2
```

`--account` 可重复，最多 16 个去重地址；不给参数时保留原来的 WETH＋不存在地址默认值。采集脚本只把原始材料放到 `.local/capture/`，不会自动推广成可信基准或提交到仓库。历史窗口和限流可能变化，重新采集失败不表示现有离线证明失效。

其他公开测试资源和待补覆盖见 [测试数据来源与覆盖](../../../docs/12-测试数据来源与覆盖.md)。
